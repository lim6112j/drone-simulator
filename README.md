# 드론 제어 시뮬레이터 🚁

쿼드콥터(드론)가 **왜 스스로 흔들리고, 어떻게 제어기가 그것을 잡는지**를 직접 실험해볼 수 있는 데스크톱 시뮬레이터입니다. 드론 비행 경험이나 제어 이론 지식이 전혀 없어도 시작할 수 있도록 만들어졌습니다.

![Rust](https://img.shields.io/badge/Rust-1.95+-orange) ![GUI](https://img.shields.io/badge/GUI-egui-blue)

## 빠른 시작

```bash
cargo run --release
```

Rust 툴체인이 설치되어 있으면 이 한 줄로 실행됩니다. ([Rust 설치](https://rustup.rs))

## 드론 기초 개념 (초보자용)

### 1. 쿼드콥터는 왜 저절로 안 날까?

드론은 본질적으로 **불안정한 시스템**입니다. 깨진 달걀을 손끝 위에서 세우는 것과 비슷해요.

- 4개의 프로펠러가 만드는 추력의 합이 몸무게보다 크면 위로, 작으면 아래로 떨어집니다
- 프로펠러 추력이 조금이라도 **비대칭**이면 기체가 기울기 시작합니다
- 한 번 기울기 시작하면 더 기울어지는 방향으로 가속되므로, **사람이 매 순간 수백 번씩 스로틀을 조절하는 것**과 같은 자동 보정이 필요합니다

이 "매 순간의 보정"이 바로 **제어기(controller)**이고, 이 시뮬레이터의 주인공입니다.

### 2. 롤 · 피치 · 요 — 기체의 세 가지 회전

드론은 3개의 축을 중심으로 회전합니다. 이 시뮬레이터의 좌표계는 **x=전방, y=좌측, z=상방**입니다.

| 회전 | 축 | 의미 | 이 시뮬레이터에서 |
|---|---|---|---|
| **롤(Roll)** | x축 (전방) | 좌우로 기울임 | 왼쪽 모터가 세지면 좌측이 올라감 (+) |
| **피치(Pitch)** | y축 (좌우) | 앞뒤로 기울임 | 앞 모터가 세지면 기수가 올라감 (−) |
| **요(Yaw)** | z축 (수직) | 방향 돌리기 | 대각선 모터 쌍의 회전 속도 차이 |

**기울이면 왜 이동하나?** 추력은 기체가 서있는 방향(기체 아래쪽)으로 나옵니다. 기체를 앞으로 기울이면 추력의 일부가 앞쪽 성분이 되어 전진합니다. 헬리콥터가 앞으로 기울여 전진하는 것과 같은 원리입니다. 이 시뮬레이터에서 "수평 스텝" 미션을 실행하면 컨트롤러가 기체를 먼저 기울인 다음 목표점으로 이동하는 것을 상단 뷰에서 볼 수 있습니다.

### 3. 4개의 모터는 어떻게 조합되나? (믹싱)

모터 배치는 `[FL, FR, RL, RR]` (앞왼쪽, 앞오른쪽, 뒤왼쪽, 뒤오른쪽)입니다.

- **위로 뜨기**: 4개 모두 세게
- **앞으로 기울이기**: 뒤쪽 모터를 앞쪽보다 세게
- **오른쪽으로 기울이기**: 왼쪽 모터를 오른쪽보다 세게
- **요(회전)**: 대각선 쌍(FL+RR vs FR+RL)의 속도 차이 — 프로펠러는 회전 반작용으로 기체를 반대로 비틀려고 하기 때문

이렇게 "원하는 회전 힘 → 각 모터의 출력"으로 바꾸는 계산을 **믹싱(mixing)**이라고 합니다. 컨트롤러가 매 스텝마다 수행하는 마지막 단계입니다.

### 4. PID 제어 — 가장 널리 쓰이는 피드백 제어

목표와 현재 상태의 **오차(error)**를 줄이기 위해 세 가지 성분을 합산합니다:

```
출력 = Kp × 오차            ← P (비례): 오차가 크면 강하게 밀기
     + Ki × 오차의 누적합    ← I (적분): 오래 남은 오차를 없애기
     + Kd × 오차의 변화속도  ← D (미분): 급격한 변화를 부드럽게 잡기
```

- **P만 쓰면**: 목표 근처에서 왔다 갔다 진동합니다 (스프링만 있는 것과 같음)
- **I가 필요한 이유**: 바람이 계속 밀면 오차가 계속 발생하는데, I항이 이 오차를 시간이 갈수록 누적해서 정확히 상쇄합니다. **바람 실험에서 핵심 역할**입니다
- **D가 필요한 이유**: 빨리 접근하다가 목표를 지나쳐 튀는 것(오버슈트)을 줄여줍니다

### 5. 캐스케이드(직렬) 제어 — 이 시뮬레이터의 구조

"어디로 갈까 → 어떻게 기울일까 → 모터는 얼마나?"를 단계로 나눕니다:

```
위치 명령 (2m 앞으로 가라)
   ↓ 위치 P 제어 → 원하는 속도
속도 PID → 원하는 가속도 (기울기 각 + 추력)
   ↓
자세 P 제어 → 원하는 회전 각속도
   ↓
각속도 PID → 각 모터 출력 (믹싱)
```

한 번에 다 처리하려는 단일 루프보다 안정적이고 튜닝이 쉬워서, 실제 드론 펌웨어(Betaflight, PX4, ArduPilot)도 같은 구조를 씁니다.

### 6. 모터 지연 — 이 실험의 핵심 변수

실제 드론에서 명령이 즉시 실행되지 않습니다. 이 시뮬레이터는 두 가지 지연을 모델링합니다:

- **순수 지연(death time)**: 명령 후 아무 일도 안 일어나는 시간. 통신 지연, 센서 처리 시간 등
- **시상수 τ (first-order lag)**: 명령을 받아도 모터가 서서히 회전수가 올라가는 관성. 프로펠러+모터의 물리적 관성

**왜 중요한가?** 컨트롤러는 1ms마다 "지금 상태가 이래서, 고쳐라"라고 명령합니다. 그런데 그 명령이 100ms 뒤에야 실행된다면, 실행될 때쯤엔 상황이 이미 바뀌어서 **엉뚱한 방향으로 교정**하게 됩니다. 지연이 길어질수록 같은 게인으로도 시스템이 불안정해집니다 — 슬라이더로 직접 확인해 보세요.

## 시뮬레이터 사용법

### 화면 구성

- **상단 바**: 미션 선택, 바람 펄스, 일시정지/리셋, 배속(0.1–5×), 프리셋
- **좌측 패널**: 모든 파라미터 슬라이더 — 움직이면 **리셋 없이 즉시 적용**됩니다
- **중앙**: 2D 시각화 (측면 = x–z 평면, 상단 = x–y 평면). 궤적·목표점·바람 화살표 표시
- **하단**: 실시간 그래프 (위치 오차 / 자세 / 모터 출력 탭)

### 실험 추천 순서

1. **기본 호버 관찰** — 아무것도 만지지 말고 기체가 목표점에 머무는지 확인
2. **바람 펄스** — "바람 펄스" 버튼을 누르면 밀렸다가 복귀합니다. 하단 그래프에서 오차가 지수적으로 감쇠하는 모습을 보세요 (I항의 역할)
3. **I 게인 실험** — `속도 I`를 0으로 내리면 바람을 이길 수 없게 됩니다 (정상 상태 오차 발생)
4. **지연 실험 (핵심!)** — `순수 지연` 슬라이더를 0 → 100 → 200 → 300ms로 올리며 그래프의 진동을 관찰하세요. 같은 게인인데 지연만으로 붕괴하는 것을 볼 수 있습니다
5. **D 게인 실험** — `속도 D`를 크게 하면 오버슈트가 줄지만, 지연이 있을 때는 D항이 오히려 진동을 유발할 수 있습니다
6. **불안정 프리셋** — 지연 250ms로 기본 튜닝도 무너지는 교육용 시나리오

### 미션

| 미션 | 내용 |
|---|---|
| 호버 | 시작 위치 유지 |
| 수직 스텝 | 2초 후 지정 높이로 상승 (기본 +2m) |
| 수평 스텝 | 2초 후 지정 거리만큼 이동 (기본 +3m) |

### 프리셋

| 프리셋 | 내용 |
|---|---|
| 기준 튜닝 | 잘 튜닝된 기본값 |
| 지연 과다 | 지연 150ms + 느린 모터 — 응답이 느려짐 |
| 느린 모터 | 시상수 300ms — 모터 관성이 큼 |
| 강풍 | 5 m/s 기저풍 + 3 m/s 스텝 돌풍 |
| 불안정 | 지연 250ms — 기본 튜닝으로도 진동·붕괴 |

기체가 너무 멀리 나가거나 수치가 비정상이 되면 시뮬레이션이 멈추고 **"발산 — 리셋하세요"** 오버레이가 표시됩니다.

## 실제 드론 실측 스펙 적용하기

자유 슬라이더 실험이 익숙해지면, 실제 기체의 측정치로 시뮬레이션을 돌려볼 수 있습니다.

```bash
# 5인치 프리스타일 쿼드 (600g, 2207 모터, 실측 지연 18ms/τ 55ms)
cargo run -- examples/real_drone_5inch.toml

# 65mm 타이니후프 (25g, 브러시드 모터 — 지연과 관성이 훨씬 큼)
cargo run -- examples/real_drone_tinywhoop.toml
```

두 예제는 공개 스펙·스러스트 스탠드 측정 보고의 **대표값 범위**를 종합한 것입니다. 자체 기체를 적용하려면:

1. **질량**: 저울로 측정한 전비중량(kg)
2. **최대 추력 `tmax`**: 모터 1개의 정지 최대 추력(N). 스러스트 스탠드 데이터가 없으면 제조사 스펙표 사용
3. **모터 지연 `delay_s` / `tau_s`**: 스텝 응답 측정이 가장 좋습니다. 없으면 기체급별 대표값(예제 파일 주석 참고)으로 시작
4. **관성 `inertia`**: 실측이 어려우면 `I ≈ (1/12)·m·L²` 근사
5. **게인**: 기체가 바뀌면 재튜닝이 필요합니다 — 기본 게인으로 시작해 슬라이더로 조정

TOML 파싱에 실패하면 기본 파라미터로 시작하고 콘솔에 원인을 출력합니다.

### 참고: 스펙 문서에 실측치가 있을까?

대부분의 완제품 스펙 문서에는 시뮬레이션에 필요한 수치가 **일부만** 있습니다:

**스펙 문서에서 바로 확보 가능** ✅

| 항목 | 어디서 |
|---|---|
| 질량 | 제품 스펙표 (예: "249 g") |
| 휠베이스 | 스펙표 — `arm_length` = 절반 |
| 모터당 최대 추력 `tmax` | 모터 제조사 추력표 (T-Motor, EMAX 등: "2207 1750KV @14.8V → 1,350 g" → 13.2 N) |
| 모터/프로펠러/배터리 모델명 | 스펙표 — 측정 데이터를 찾는 단서 |

**스펙 문서에 없음 — 별도 확보 필요** ❌

| 항목 | 현실적 확보 방법 |
|---|---|
| 순수 지연 `delay_s` | 직접 측정(스러스트 스탠드+오실로스코프) 또는 기체급 커뮤니티 측정치 (5인치: 15–25 ms) |
| 시상수 `tau_s` | 스텝 응답 곡선에서 63% 도달 시간 측정, 없으면 기체급 대표값 |
| 관성 `inertia` | 논문(바이필러 진자), CAD 질량속성, 또는 근사 `I ≈ (1/12)·m·L²` |
| 항력 계수 `drag_*` | 풍동 데이터는 연구용뿐 — 항풍 등급("레벨 5")에서 역산하거나 논문값 사용 |

**실무 워크플로**: ① 스펙 문서에서 확보 가능한 것만 복사 → ② 나머지는 근사/대표값으로 시작 → ③ 시뮬레이션 특성과 실비행을 비교하며 보정. 이 예제 저장소의 TOML도 이 방식으로 종합한 대표값입니다.

## 아키텍처

```
src/
├── main.rs       # eframe 앱 진입점, 한글 폰트 로드
├── app.rs        # egui UI (슬라이더 → 즉시 적용)
├── sim.rs        # 1kHz 고정 스텝 시뮬레이션 코어
├── drone.rs      # 쿼터니언 강체 동역학 (중력, 항력, 토크)
├── motor.rs      # 모터: 순수 지연 + 1차 지연 + 추력 = k·ω²
├── wind.rs       # 바람 생성기 (기저풍/돌풍/펄스)
├── control/
│   ├── pid.rs        # 안티와인드업 PID
│   └── cascade.rs    # 5단 캐스케이드 컨트롤러 + 믹싱
├── params.rs     # 파라미터 구조체 + TOML 직렬화
├── presets.rs    # 원클릭 실험 프리셋
├── viz.rs        # 2D 시각화
└── plots.rs      # 실시간 그래프
```

- 물리는 **1kHz 고정 스텝**으로 적분되어, UI 프레임률과 무관하게 결정론적으로 동작합니다
- 컨트롤러는 `Controller` 트레이트 뒤에 숨겨져 있어, 향후 LQR/MPC/강화학습 컨트롤러로 교체 실험이 가능합니다
- 파라미터는 TOML로 직렬화되어 실제 기체 스펙을 적용할 수 있습니다

## 실제 드론 시스템으로의 확장
