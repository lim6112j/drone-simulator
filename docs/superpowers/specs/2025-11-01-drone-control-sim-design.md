# 드론 제어 시뮬레이터 — 설계 문서

날짜: 2025-11-01
상태: 승인 대기

## 1. 의도와 배경

모터 지연 시간이 드론 제어 성능에 주는 영향을 눈으로 보고 실험할 수 있는
인터랙티브 시뮬레이터. 모터/프로펠러의 응답 지연(순수 지연 + 1차 시간 지연)이
커질수록 제어기가 늦게 반응해 진동·발산이 생기는 현상을, 슬라이더를 움직이는 즉시
확인하는 것이 핵심 경험.

최종 목표는 학습/실험 도구이며, 추후 실제 드론의 실측 수치(지연, 시상수, 질량 등)를
설정 파일로 교체해 "실기 사전 튜닝 도구"로 확장할 수 있는 구조를 가진다.

## 2. 목표

- 4모터 쿼드콥터 강체 역학 시뮬레이션 (추력 차이 → 자세 → 위치)
- 모터 지연 모델: 순수 지연(dead time) + 1차 시간 지연, 둘 다 조절 가능
- 바람 교란: 일정 풍 + 돌풍(스텝/사인/완화 랜덤), 세기·방향 조절
- 제어 과제 3종: 제자리 호버, 수직 이동(스텝 명령), 수평 이동(스텝 명령)
- 제어기: 위치 → 속도 → 자세 → 각속도 캐스케이드 PID (적분 포함, anti-windup 필수)
- UI: 슬라이더/버튼만으로 모든 실험 가능 (코드 수정 불요)
- 실시간 그래프: 위치 오차, 자세, 모터 출력, 지연 큐 상태
- 2D 시각화: 측면 뷰 + 상단 뷰, 기체 기울기 표시, 궤적
- 프리셋 시나리오: "튜닝됨", "지연 과다(진동)", "느린 모터", "강풍" 등 원클릭 비교
- 설정 파일(TOML) 저장/불러오기 → 나중에 실기 수치로 갈아끼우기

## 3. 비목표 (Non-goals)

- 강화학습, LQR, MPC 등 다른 제어기의 구현 (단, 확장 여지는 설계로 열어둠 — 아래 §7)
- 3D 그래픽
- 실기 하드웨어 연동 (HIL)
- 정밀 공력 모델 (프롭 웨시, 지면 효과, 블레이드 플래핑 등)
- 배터리/전압 강하 모델

## 4. 반목표 (Anti-goals — 이러면 실패)

- 조종 게임처럼 변한다 (조종 연습 도구가 아님, 제어 알고리즘이 주인공)
- 지연의 영향이 안 보인다 (지연을 숨기거나 평균 내면 핵심 가치 상실)
- 연구용 고정밀 시뮬레이터가 되려고 범위가 부풀어 오른다

## 5. 제약

- Rust (stable), 단일 실행파일, 네트워크 불필요, macOS/Linux 동작
- 물리는 고정 스텝(기본 1 kHz), UI는 60 fps — 시뮬레이션 루프와 렌더 루프 분리
- 지연 슬라이더는 물리 스텝의 정수 배로 양자화 (지연 라인 = 링 버퍼)

## 6. 접근 방법 비교

| 접근 | 장점 | 단점 | 판정 |
|------|------|------|------|
| **A. Rust 네이티브 (egui + egui_plot)** | 실행파일 하나, 오프라인 동작, 슬라이더 즉시 반응, 실시간 그래프 동일 화면 | 화면 공유 시 상대방도 프로그램 필요 | **채택** |
| B. Rust→WASM + 웹 UI | 링크 공유 용이, UI 예쁨 | 코어+프론트엔드 2벌 관리, 개발량 ~2배, 그래프 직접 구현 | 기각 |
| C. Rust 코어 + Python 시각화 | 개발 빠름 | 슬라이더 경험 어색, 배포 이중 환경 | 기각 |

채택 이유: "슬라이더를 움직이는 즉시 결과가 보여야 한다"가 핵심 요구였고,
A가 요구 대비 개발량이 가장 적으면서 즉시성이 가장 높음.

## 7. 결정된 사항

### 7.1 기술 스택 (사용자 결정)
- 언어: Rust (속도 문제 — 사용자 지정)
- UI 방식: 슬라이더/버튼 기반, 컨트롤러 코드는 사용자가 수정하지 않음 (사용자 지정)
- 앱 형태: 네이티브 데스크톱 앱 (사용자 결정 — 접근 A)

### 7.2 제어 구조 (대화에서 확정)
- 주인공 제어기: 캐스케이드 PID
  - 위치 P(D) → 속도 PID → 목표 자세(roll/pitch) + 수직 추력 → 자세 PID → 각속도 PID → 모터 믹싱(X-형 믹싱 행렬)
- 적분(I) 항으로 일정 바람 상쇄, anti-windup(조건부 적분 또는 back-calculation) 필수 —
  지연 + 포화 조합에서 windup이 진동을 악화시키므로 교육적 포인트이기도 함
- 컨트롤러는 trait 인터페이스 뒤에 위치 → 추후 RL/LQR/MPC 비교 실험 가능 (v1에서는 구현하지 않음 — 대화에서 합의)

### 7.3 물리/지연 모델 (대화에서 확정)
- 강체: 위치/속도/자세/각속도, 중력, 선형+제곱 항공 저항, 바람은 상대풍으로 작용
- 자세는 쿼터니온 권장 (오일러 특이점 회피) — [빌더 판단 여지]
- 모터: 명령 u∈[0,1] → 순수 지연 Td → 1차 지연(시상수 τ) → 추력 = k·ω², 포화 [0, Tmax]
- 지연 슬라이더 범위: 0–300 ms, 시상수 범위: 0–500 ms (대략, 빌더에서 다듬음)

### 7.4 UI 구성
- 좌측: 파라미터 슬라이더 (PID 게인 그룹 / 모터·지연 그룹 / 바람 그룹 / 기체 스펙 그룹)
- 중앙: 2D 시각화 (측면/상단 전환, 기체 기울기 화살표, 목표점 마커, 궤적)
- 하단: 실시간 그래프 탭 (위치 오차 / 자세·각속도 / 모터 출력 4채널)
- 상단: 과제 선택(호버/수직/수평), 바람 펄스 버튼, 일시정지/리셋, 배속
- 프리셋 드롭다운: 기준 튜닝 / 지연 과다 / 느린 모터 / 강풍 / 불안정
